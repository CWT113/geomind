# 类型断言

类型断言（Type Assertion）允许开发者手动覆盖 TS 的类型推断结果，类似于其他语言的类型转换。它仅在编译阶段生效，不产生任何运行时代码。

```ts {2}
const str1: any = "hello";
const len1: number = (str1 as string).length;
```



## 处理 any/unknown 类型

从外部接口、JSON 解析等场景获取的数据通常为 any，此时可以通过断言来恢复类型提示。

```ts {8}
interface User {
  name: string;
  age: number;
}

const response: any = { name: "tom", age: 20 };
// 断言为具体类型，获得类型提示
const user = response as User;

console.log(user.name);
console.log(user.age);
```



## 操作 DOM 元素

`document.querySelector` 返回的是 `Element | null`，断言为具体元素类型后才能访问其专属属性。

```ts {1}
const input = document.querySelector("#username") as HTMLInputElement;

// 更安全的写法：先判空再断言
const btn = document.querySelector("#submit");
if (btn) {
  (btn as HTMLButtonElement).disabled = true;
}
```



## 非空断言

在值后面加 `!`，可以告诉编译器该值不为 null 或 undefined，适用于你明确知道当前值一定不为空的情况。

```ts {2}
function printLength(str?: string) {
  console.log(str!.length);
}
```

> [!WARNING] 注意
>
> 非空断言会绕过编译器的空值检查，若实际值为 null/undefined，运行时仍会抛出错误。在允许的情况下优先使用可选链 `?.` 代替。



## 常量断言

`as const` 将字面量推断为最窄的只读字面量类型，常用于定义枚举值、配置常量和元组。

```ts
// 推断为 readonly 只读，控制元素和长度均不可变
const color = ["red", "green", "blue"] as const;
color.push("yellow"); // 语法错误：只读数组不能push // [!code --]

const config = {
  host: "localhost",
  port: 8080
} as const;
config.port = 9000; // 语法错误：port是只读的 // [!code --]
```



## 双重断言

当两个类型之间没有重叠关系，TS 会拒绝直接断言。此时可以借助 unknown 作为中转，这是危险操作，应尽量避免。

```ts {7}
const num = 100;

// 直接断言：number 与 string 无重叠，编译器会报错
const str1 = num as string; // [!code --]

// 双重断言：先断言为 unknown，再断言为目标类型
const str2 = num as unknown as string;
```

> [!WARNING] 警告
>
> 双重断言会完全绕过 TS 的类型系统，极易引发运行时错误。仅在处理第三方库类型不准确等特殊情况下使用，并在代码中注明原因。
