# 缓存

MyBatis 中的缓存，简单来说就是 **把查询过的数据暂时保存起来，下次执行相同或符合条件的查询时，尽量直接从缓存中获取数据**，而不是再次查询数据库，从而提高查询效率。

MyBatis 主要有两种缓存机制：

- **一级缓存**：将查询到的数据存储到 `SqlSession` 中，默认开启，无法通过代码干预；
- **二级缓存**：将查询到的数据存储到 `SqlSessionFactory` 中，是 Mapper（命名空间）级别的缓存，需要手动开启。二级缓存可以选择开启或关闭，也可以使用其他第三方缓存代替，如 Redis；

> [!NOTE] 提示
>
> MyBatis 中的缓存只针对于 `select` 语句，增、删、改是不支持缓存的。



## 一级缓存

> [!TIP]
>
> 一级缓存最关键的特点：它只能在同一个 `SqlSession` 内共享。

如果两次查询在同一个 `SqlSession` 中执行，且中间没有清空缓存等影响，那么第二次查询通常直接从一级缓存中获取结果。

```java
@Test
void testSelectAll() {
  SqlSession sqlSession = MybatisUtils.getSqlSession();
  SysUserMapper mapper = sqlSession.getMapper(SysUserMapper.class);
  List<SysUser> sysUsers1 = mapper.selectAll(); // 查询数据库
  
  List<SysUser> sysUsers2 = mapper.selectAll(); // 命中一级缓存 // [!code ++]
}
```

一级缓存失效的情况：

|                情况                | 一级缓存影响                       |
| :--------------------------------: | ---------------------------------- |
|     同一个 SqlSession 重复查询     | 通常命中缓存                       |
|        执行 增、删、改 操作        | 默认清空当前 SqlSession 的本地缓存 |
| 手动调用 `sqlSession.clearCache()` | 清空当前 SqlSession 的缓存         |
|          关闭 SqlSession           | 缓存随会话结束而失去作用           |
|       换一个 SqlSession 查询       | 不共享原来的一级缓存               |

```java
User user1 = mapper.selectById(1); // 查询数据库

mapper.updateName(1, "张三");      // 更新操作，默认清空一级缓存

User user2 = mapper.selectById(1); // 再次查询数据库
```



## 二级缓存

二级缓存是 Mapper 命名空间级别的缓存，可以被同一个命名空间下的多个 `SqlSession` 共享。与一级缓存不同，二级缓存默认不需要开启，需要配置。

首先，在 `mybatis-config.xml` 中启用缓存机制：

::: info

`cacheEnabled` 默认就是 `true`，通常不需要专门设置。真正关键的是在 Mapper 中 **声明缓存**。

:::

```xml
<settings>
  <setting name="cacheEnabled" value="true"/>
</settings>
```

然后，在对应的 Mapper XML 文件中添加：

```xml {7}
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mapper.SysUserMapper">
  <!-- 开启当前命名空间的二级缓存 -->
  <cache/>

  <select id="selectAll" resultType="com.example.pojo.SysUser">
    select * from sys_user
  </select>
</mapper>
```

> [!WARNING] 注意
>
> - 二级缓存通常在事务提交或 `SqlSession` 关闭时，将相关查询结果写入共享缓存。因此，刚执行完查询就立即换一个会话查询，不一定会命中缓存；
> - 默认的 `<cache/>` 配置要求缓存对象能够序列化；



当执行当前 Mapper 中的增删改操作时，相关的二级缓存会被清空，此时二级缓存将失效。
