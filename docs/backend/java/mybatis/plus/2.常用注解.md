# 常用注解

## @TableName

`@TableName` 用于 **指定数据库表名**。默认情况下，MyBatis-Plus 会根据实体类名称转下划线去匹配表。如果数据库表名称与实体类名称不一致时，就需要通过 `@TableName` 来显式指定表名。

```java {2}
@Data
@TableName("sys_user") // 明确告诉 MyBatis-Plus，对应 sys_user 表
public class SysUser {
  private Long id;

  private String userName;
}
```



## @TableId

`@TableId` 用于 **指定主键和生成策略**。假设数据库表的主键是 `user_id`，并且使用 MySQL 自增策略：

```java {4}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO) // 明确告诉 MyBatis-Plus 主键叫 user_id，并且使用自增主键
  private Long userId;

  private String userName;
}
```

常见的 `IdType` 有以下几种类型：

| 类型        | 含义                       | 典型场景 |
| :---------: | :------------------------- | -------- |
| AUTO        | 数据库自增                 | MySQL 自增主键 |
| INPUT       | 由业务代码自行提供         | 外部系统指定主键 |
| ASSIIGN_ID  | 由 MyBatis-Plus 分配雪花 ID | 默认 ID 生成器，常用于分布式系统 |
| ASSIGN_UUID | 由 MyBatis-Plus 分配 UUID    | 使用字符串类型主键 |



## @TableField

`@TableField` 用于 **指定字段与数据库列的关系**。这是使用最高频的注解，主要有四种用途。



### 列名不一致

`@TableField` 最主要的用途是当 **实体类中属性名与表中字段不一致时，用它来显式指定名称。**

```java {7}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO)
  private Long userId;

  @TableField("nick_name") // 明确告诉 MyBatis-Plus，表中的字段叫 nick_name，而不是 name
  private String name;
}
```

> [!NOTE] 注意
>
> 特别的，如果实体类中 **属性名是以 `isXxx` 开头，并且是 `Boolean` 类型**，此时必须显式指定名称。
>
> 这是因为这种字段 MyBatis-Plus 底层反射处理时，会自动把 `is` 去掉，这将会导致和数据库表中的字段名称不一致。
>
> ```java {10}
> @Data
> @TableName("sys_user")
> public class SysUser {
>   @TableId(value = "user_id", type = IdType.AUTO)
>   private Long userId;
> 
>   @TableField("nick_name")
>   private String name;
>   
>   @TableField("is_married") // 必须显式指明字段名
>   private Boolean isMarried;
> }
> ```



### 排除字段

假设 `address` 字段只是前端传入的查询条件，而并不是 `sys_user` 表中的字段，此时可以将其排除。

```java {10}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO)
  private Long userId;

  @TableField("nick_name")
  private String name;

  @TableField(exist = false) // 排除该字段，不会在 SQL 中出现
  private String address;
}
```



### 控制更新行为

如果想要把一个字段值明确的更新为 `null` 值，直接写 `null` 是会报错的：

```java
@Test
void testUpdateById() {
  SysUser sysUser = SysUser.builder()
    .userId(3L)
    .userName(null) // 报错：想把 user_name 更新为 null！ // [!code --]
    .build();
  int affectRows = sysUserMapper.updateById(sysUser);
  System.out.println(affectRows);
}
```

此时可以借助 `@TableField` 进行配置，允许将其更新为 `null` 值：

```java {7}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO)
  private Long userId;

  @TableField(updateStrategy = FieldStrategy.ALWAYS) // 允许把值更新为 null
  private String username;
}
```



### 与关键字冲突

假设有一个字段叫 `order` 字段，而 `order` 是数据库进行排序的关键字，此时查询就会起冲突。

```java {10}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO)
  private Long userId;

  @TableField("nick_name")
  private String name;

  @TableField("`order`") // 通过反引号显式指定字段名称，此时在 SQL 中会使用 `order` 查询，就不会和关键字冲突了
  private Integer order;
}
```
