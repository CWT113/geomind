# 逻辑删除

逻辑删除是基于代码逻辑模拟删除效果，但并不会真正删除数据。思路如下：

- 在表中添加一个字段（如：`is_deleted`）用来标记数据是否被删除；
- 当删除数据时把该字段标记为 `1`（或 true），没有被删除时标记为 `0`（false）；
- 查询时只查询标记为 `0` 的数据；

> [!WARNING] 注意
>
> 逻辑删除本身也有自己的局限性，比如：
>
> - 会导致数据库表中的垃圾数据越来越多，影响查询效率；
> - SQL 中全都要对逻辑删除的字段做判断，影响查询效率；
>
> 因此，逻辑删除有好也有坏，视情况而使用。如果数据必须要保留，不能物理删除，可以采用把 **数据迁移到其他表的办法**，即删除的时候，从主表把数据迁移到删除表中，保持主表的干净。



## 全局配置

MyBatis-Plus 提供了逻辑删除功能，**无需改变方法调用的方式**，而是在底层帮我们自动修改 CRUD 的语句。因此需要在全局进行配置：

```yaml
mybatis-plus:
  global-config:
    db-config:
      # 全局逻辑删除的实体字段名，字段类型可以是 boolean、integer
      logic-delete-field: isDelete # 注意是实体类的名称，不是数据库的字段名
      # 逻辑已删除值（默认为 1）
      logic-delete-value: 1
      # 逻辑未删除值（默认未 0）
      logic-not-delete-value: 0
```



## 基础使用

在增删改查时，MyBatis-Plus 会自动在 SQL 中拼接 `is_delete = 0`，从而实现逻辑删除。

值得注意的是，当执行删除操作时，开启了逻辑删除后，底层执行的是 `update` 语句，而非 `delete` 语句。

::: code-group

```java [单元测试] {10,18,25,26}
@SpringBootTest
class MainApplicationTests {
  @Autowired
  private SysUserService sysUserService;

  @Test
  @DisplayName("查询所有")
  void testQueryAll() {
    List<SysUser> sysUsers = sysUserService.list();
    // select * from sys_user where is_delete = 0
    sysUsers.forEach(System.out::println);
  }

  @Test
  @DisplayName("根据Id查询")
  void testQueryById() {
    SysUser sysUser = sysUserService.getById(1);
    // select * from sys_user where user_id = ? and is_delete = 0
    System.out.println(sysUser);
  }

  @Test
  @DisplayName("根据Id删除")
  void testDeleteById() {
    boolean isSuccess = sysUserService.removeById(3);
    // update sys_user set is_delete=1 where user_id=? and is_delete=0
    System.out.println(isSuccess);
  }
}
```

```java [SysUser] {18}
@Data
@TableName("sys_user")
public class SysUser {
  @TableId(value = "user_id", type = IdType.AUTO)
  private Long userId;

  private String userName;

  private String nickName;

  private String password;

  private LocalDateTime createTime;

  private LocalDateTime updateTime;

  @TableField(value = "is_delete")
  private Integer isDelete;
}
```
