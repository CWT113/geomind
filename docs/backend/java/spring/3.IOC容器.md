# IoC 与容器

## 容器

Spring6 中的容器指的是 IoC 容器，它是 Spring 框架的核心机制，本质上是一个用于管理应用中 Bean（对象）的生命周期和依赖关系的工厂。

> [!NOTE] 容器的核心功能
>
> - **读取配置**：读取开发者定义的配置元数据（如 Java 配置类、注解或 XML 文件）；
> - **实例化与装配**：根据配置创建 Bean 对象，并将所需的依赖注入到对象中；
> - **管理生命周期**：负责 Bean 从初始化、使用、销毁的全过程；

> [!TIP] 容器的核心接口
>
> - **`BeanFactory`（基础容器）**：Spring 框架最底层的接口，提供基本的依赖注入支持。采用延迟加载策略，只有用到 Bean 时才去创建；
> - **`ApplicationContext`（高级容器）**：`BeanFactory` 的子接口，也是 Spring 开发中最常用的容器。它在容器启动时就会预先实例化单例 Bean，并整合了国际化、事件发布、AOP 等高级特性；



在基于 Java17+ 的 Spring6 开发中，推荐使用基于注解和配置类的容器实现：

|               容器类               | 说明与使用场景                                               |
| :--------------------------------: | ------------------------------------------------------------ |
| AnnotationConfigApplicationContext | 最常用。用于基于 Java 配置类（注解如 `@Configuration`、`@ComponentScan`）启动容器 |
|   ClassPathXmlApplicationContext   | 传统方式，从类路径加载 XML 配置文件启动容器                  |
|    GenericWebApplicationContext    | Web 应用场景下的标准容器实现                                 |





## 控制反转（IoC）

控制反转（Inversion of Control，简称 IoC）是 Spring6 框架的核心设计思想，主要用来降低程序代码之间的耦合度。

::: info 什么是“控制”？什么是“反转”？

- **传统开发（正向控制）**：当对象 A 需要用到对象 B 时，必须由 A 亲自创建对象 B（如通过 `new B()`）。对象的创建、依赖关系的处理以及生命周期都由开发者在代码中硬编码控制。

- **控制反转（反向控制）**：对象的创建、管理和装配控制权交给了 Spring IoC 容器。当对象 A 需要用到对象 B 时，Spring 容器会自动创建 B 并注入到 A 中。

:::



## 依赖反转（DI）

控制反转是一种 **设计思想**，而依赖注入（Dependency Injection，DI）是实现 IoC 的 **具体技术手段**。

在 Spring6 中，最推荐的实现方式是构造器注入：

```java
@Service
public class UserService {
  private final UserRepository userRepository;

  // Spring 6 中，若类只有一个构造函数，可省略 @Autowired 注解
  public UserService(UserRepository userRepository) {
    this.userRepository = userRepository;
  }
}
```
