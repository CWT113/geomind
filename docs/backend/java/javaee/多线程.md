# 多线程

多线程是指在一个程序中同时运行多个“执行路径”（即线程）的技术。它允许程序将不同的任务拆分并发执行，从而充分利用 CPU 的多核性能，提高程序的响应速度和吞吐量。

要理解多线程，首先需要区分 **进程（Process）** 和 **线程（Thread）**：

- **进程**：操作系统进行资源分配和调度的基本单元（如打开的浏览器或音乐播放器），每个进程拥有独立的内存空间；
- **线程**：进程内部的独立执行路径，是 CPU 调度的最小单位，**同一个进程内的多个线程** 会共享该进程的内存资源；

> [!NOTE] 多线程优势
>
> - **提高 CPU 利用率**：在单线程下，如果程序在等待磁盘 IO 或网络请求，CPU 就会处于闲置状态，多线程可以在等待数据时切去执行其他任务；
>
> - **提高应用响应速度**：在 GUI 应用或 web 服务中，将耗时任务放入后台线程执行，主线程可以继续响应用户的点击或请求；



## 创建线程

### 继承 Thread 类

继承 Thread 类，并重写 `run()` 方法，调用 `start()` 启动线程。

```java {9}
public static void main(String[] args) {
  MyThread myThread1 = new MyThread();
  myThread1.start(); // 当前线程名称：Thread-0

  MyThread myThread2 = new MyThread();
  myThread2.start(); // 当前线程名称：Thread-1
}

public class MyThread extends Thread {
  @Override
  public void run() {
    String name = Thread.currentThread().getName();
    System.out.println("当前线程名称：" + name);
  }
}
```



### 实现 Runnable 接口

解耦任务与线程本身，避免了 Java 单继承的限制，推荐写法。

```java {6}
public static void main(String[] args) {
  Thread thread1 = new Thread(new MyRunnable());
  thread1.start(); // 当前线程名称：Thread-0
}

public class MyRunnable implements Runnable {
  @Override
  public void run() {
    String name = Thread.currentThread().getName();
    System.out.println("当前线程名称：" + name);
  }
}
```



### 实现 Callable 接口

与 Runnable 不同，Callable 允许线程 **带返回值** 并抛出受检异常。

```java {11,15}
public static void main(String[] args) throws Exception {
  Callable<Integer> task = () -> {
    int sum = 0;
    for (int i = 0; i < 100; i++) {
      sum += i;
    }
    return sum;
  };

  // 使用 FutureTask 创建任务载体
  FutureTask<Integer> futureTask = new FutureTask<>(task);
  new Thread(futureTask).start();

  // get()会阻塞直到获取线程计算的结果
  Integer result = futureTask.get();
  System.out.println("计算结果：" + result); // 计算结果：4950
}
```

::: info 关键解释

- task 是一个实现了 `Callable<Integer>` 接口的对象。它里面包含了你要在后台执行的具体逻辑，并且会返回一个 Integet 类型的结果；
- `FutureTask` 它是一个“桥梁”兼“容器”：
  - 充当桥梁：因为 Thread 类只认识 Runnable 接口，不认识 Callable。而 FutureTask 实现了 Runnable 接口，因此它可以被传递给 Thread；
  - 充当容器：它同时实现了 `Future` 接口，用来存储后台线程执行完 task 后返回的结果，或者捕获执行中抛出的异常；


:::



### 线程池 ExecutorService

在实际生产中，频繁创建和销毁线程会带来很大的资源开销。通过线程池可以复用线程，便于管理和调优。

```java {3,8,13}
public static void main(String[] args) {
  // 创建固定大小为 3 的线程池
  ExecutorService executor = Executors.newFixedThreadPool(3);

  for (int i = 0; i < 5; i++) {
    final int taskId = i;
    // 提交任务给线程池使用
    executor.submit(() -> {
      System.out.println("任务 " + taskId + " 正在由 " + Thread.currentThread().getName() + " 执行");
    });
  }
  // 关闭线程池
  executor.shutdown();
}
```



## 线程安全

当多个线程同时访问同一个资源时，并且至少有一个线程正在修改这个资源，此时如果不加控制，就可能导致数据错乱，结果不一致甚至程序崩溃。

::: info 经典案例：并发扣减库存/卖票

假设库存只有 1 个，两个线程同时来买商品：

```tex
线程 A 检查库存：发现还有 1 个  ──┐
                              ├──> 两个线程都认为有货，都执行了扣减！导致库存变成了-1
线程 B 检查库存：发现还有 1 个  ──┘    
```

这就是典型的竞态条件。

:::

在并发编程中，线程安全问题本质上都是因为打破了以下三个特性中的一个或多个：

::: info ① 原子性（Automicity）

- 含义：一个或多个操作，要么全部执行成功且不被打断，要么全部不成功；

- 反例：看似简单的 `count++` 操作，在 CPU 底层其实可以分为 3 步：
  - 读取 count 的值
  - 将值 +1
  - 将新值重新写回内存
  - 如果在第 1 步和第 3 步之间，其他线程插进来修改了 count，数据就会出错

:::

::: info ② 可见性（Visibility）

- 含义：当一个线程修改了共享变量的值，其他线程能够立即看到最新的值；
- 原因：CPU 为了提高效率，每个线程都有自己的 **工作内存**。线程修改变量时，先改的是自己的本地缓存，不一定回立即 **刷回主内存**，导致其他线程读取到的依然是旧数据；

:::

::: info ③ 有序性（Ordering）

- 含义：程序执行的顺序按照代码的先后顺序执行；
- 原因：编译器和 CPU 为了优化性能，会对没有依赖关系的指令进行指令重排，在单线程下这不会有问题，但在多线程下，重排可能会破坏既定的逻辑。

:::



### 互斥锁

通过加锁，强制让多线程排队访问共享资源（同一时间只允许一个线程进入）。



#### synchronized 关键字

`synchronized` 关键字是最基础、最常用的一种互斥锁机制，用于修饰代码块或方法，表示同一时刻，只允许一个线程执行被保护的代码块或方法。

> [!NOTE] 锁对象
>
> 在实际开发中，`synchronized` 主要有三种使用方式，它们锁住的对象有所不同：
>
> |     使用方式     |     作用目标     |        实际锁住的对象        |                     说明                     |
> | :--------------: | :--------------: | :--------------------------: | :------------------------------------------: |
> | 修饰普通实例方法 |   当前实例对象   |       this（当前对象）       |         进入方法前需获取当前对象的锁         |
> |   修饰静态方法   | 类的 Class 对象  |     Xxx.class（类对象）      |          进入方法前需获取当前类的锁          |
> |  修饰同步代码块  | 括号里指定的对象 | `synchronized(obj)` 中的 obj | 推荐使用，粒度更小，只锁住关键代码，效率更高 |

::: code-group

```java {6} [普通实例方法]
public static void main(String[] args) throws InterruptedException {
  SafeCounter counter = new SafeCounter();

  Thread t1 = new Thread(() -> {
    for (int i = 0; i < 10000; i++) {
      counter.increment();
    }
  });
  Thread t2 = new Thread(() -> {
    for (int i = 0; i < 10000; i++) {
      counter.increment();
    }
  });

  t1.start();
  t2.start();
  // 等待两个线程都执行完毕
  t1.join();
  t2.join();

  System.out.println("最终Count值：" + counter.getCount());
}
```

```java [SafeCounter] {5}
public class SafeCounter {
  private int count = 0;

  // 使用 synchronized 修饰普通实例方法，此时锁对象是当前的实例 this
  public synchronized void increment() {
    this.count++;
  }

  public int getCount() {
    return this.count;
  }
}
```

```java {9-11} [SafeCounter]
public class SafeCounter {
  private  int count = 0;
  // 专门用作锁的私有对象（推荐使用，安全且独立）
  private final Object  lock = new Object();

  public void increment() {
    System.out.println(Thread.currentThread().getName() + " 正在执行非同步的前置逻辑");
    // 只对关键的修改，如共享的变量单独操作加锁
    synchronized (lock) {
      this.count++;
    }
    System.out.println(Thread.currentThread().getName() + " 正在执行非同步的后置逻辑");
  }

  public int getCount() {
    return this.count;
  }
}
```
