# 多线程

多线程是指在一个程序中同时运行多个“执行路径”（即线程）的技术。它允许程序将不同的任务拆分并发执行，从而充分利用 CPU
的多核性能，提高程序的响应速度和吞吐量。

要理解多线程，首先需要区分 **进程（Process）** 和 **线程（Thread）**：

- **进程**：操作系统进行资源分配和调度的基本单元（如打开的浏览器或音乐播放器），每个进程拥有独立的内存空间；
- **线程**：进程内部的独立执行路径，是 CPU 调度的最小单位， **同一个进程内的多个线程** 会共享该进程的内存资源；

> [!NOTE] 多线程优势
>
> - **提高 CPU 利用率**：在单线程下，如果程序在等待磁盘 IO 或网络请求，CPU 就会处于闲置状态，多线程可以在等待数据时切去执行其他任务；
>
> - **提高应用响应速度**：在 GUI 应用或 web 服务中，将耗时任务放入后台线程执行，主线程可以继续响应用户的点击或请求；

## 创建线程

### 继承 Thread 类

继承 Thread 类，并重写 `run()` 方法，调用 `start()` 启动线程。

```java {9}
public static void main(String[] args) {
  MyThread myThread1 = new MyThread();
  myThread1.start(); // 当前线程名称：Thread-0

  MyThread myThread2 = new MyThread();
  myThread2.start(); // 当前线程名称：Thread-1
}

public class MyThread extends Thread {
  @Override
  public void run() {
    String name = Thread.currentThread().getName();
    System.out.println("当前线程名称：" + name);
  }
}
```

### 实现 Runnable 接口

解耦任务与线程本身，避免了 Java 单继承的限制，推荐写法。

```java {6}
public static void main(String[] args) {
  Thread thread1 = new Thread(new MyRunnable());
  thread1.start(); // 当前线程名称：Thread-0
}

public class MyRunnable implements Runnable {
  @Override
  public void run() {
    String name = Thread.currentThread().getName();
    System.out.println("当前线程名称：" + name);
  }
}
```

### 实现 Callable 接口

与 Runnable 不同，Callable 允许线程 **带返回值** 并抛出受检异常。

```java {11,15}
public static void main(String[] args) throws Exception {
  Callable<Integer> task = () -> {
    int sum = 0;
    for (int i = 0; i < 100; i++) {
      sum += i;
    }
    return sum;
  };

  // 使用 FutureTask 创建任务载体
  FutureTask<Integer> futureTask = new FutureTask<>(task);
  new Thread(futureTask).start();

  // get() 会阻塞直到获取线程计算的结果
  Integer result = futureTask.get();
  System.out.println("计算结果：" + result); // 计算结果：4950
}
```

::: info 关键解释

- task 是一个实现了 `Callable<Integer>` 接口的对象。它里面包含了你要在后台执行的具体逻辑，并且会返回一个 Integer 类型的结果；
- `FutureTask` 它是一个“桥梁”兼“容器”：
    - 充当桥梁：因为 Thread 类只认识 Runnable 接口，不认识 Callable。而 FutureTask 实现了 Runnable 接口，因此它可以被传递给
      Thread；
    - 充当容器：它同时实现了 `Future` 接口，用来存储后台线程执行完 task 后返回的结果，或者捕获执行中抛出的异常；

:::

### 线程池 ExecutorService

在实际生产中，频繁创建和销毁线程会带来很大的资源开销。通过线程池可以复用线程，便于管理和调优。

```java {3,8,13}
public static void main(String[] args) {
  // 创建固定大小为 3 的线程池
  ExecutorService executor = Executors.newFixedThreadPool(3);

  for (int i = 0; i < 5; i++) {
    final int taskId = i;
    // 提交任务给线程池使用
    executor.submit(() -> {
      System.out.println("任务 " + taskId + " 正在由 " + Thread.currentThread().getName() + " 执行");
    });
  }
  // 关闭线程池
  executor.shutdown();
}
```

## 线程安全

当多个线程同时访问同一个资源时，并且至少有一个线程正在修改这个资源，此时如果不加控制，就可能导致数据错乱，结果不一致甚至程序崩溃。

::: info 经典案例：并发扣减库存/卖票

假设库存只有 1 个，两个线程同时来买商品：

```tex
线程 A 检查库存：发现还有 1 个  ──┐
                              ├──> 两个线程都认为有货，都执行了扣减！导致库存变成了-1
线程 B 检查库存：发现还有 1 个  ──┘    
```

这就是典型的竞态条件。

:::

在并发编程中，线程安全问题本质上都是因为打破了以下三个特性中的一个或多个：

::: info ① 原子性（Automicity）

- 含义：一个或多个操作，要么全部执行成功且不被打断，要么全部不成功；

- 反例：看似简单的 `count++` 操作，在 CPU 底层其实可以分为 3 步：
    - 读取 count 的值
    - 将值 +1
    - 将新值重新写回内存
    - 如果在第 1 步和第 3 步之间，其他线程插进来修改了 count，数据就会出错

:::

::: info ② 可见性（Visibility）

- 含义：当一个线程修改了共享变量的值，其他线程能够立即看到最新的值；
- 原因：CPU 为了提高效率，每个线程都有自己的 **工作内存**。线程修改变量时，先改的是自己的本地缓存，不一定回立即
  **刷回主内存**，导致其他线程读取到的依然是旧数据；

:::

::: info ③ 有序性（Ordering）

- 含义：程序执行的顺序按照代码的先后顺序执行；
- 原因：编译器和 CPU 为了优化性能，会对没有依赖关系的指令进行指令重排，在单线程下这不会有问题，但在多线程下，重排可能会破坏既定的逻辑。

:::

### 互斥锁

通过加锁，强制让多线程排队访问共享资源（同一时间只允许一个线程进入）。

#### synchronized

`synchronized` 关键字是最基础、最常用的一种互斥锁机制，用于修饰代码块或方法，表示同一时刻，只允许一个线程执行被保护的代码块或方法。

> [!NOTE] 锁对象
>
> 在实际开发中，`synchronized` 主要有三种使用方式，它们锁住的对象有所不同：
>
> |     使用方式     |     作用目标     |        实际锁住的对象        |                     说明                     |
> | :--------------: | :--------------: | :--------------------------: | :------------------------------------------: |
> | 修饰普通实例方法 |   当前实例对象   |       this（当前对象）       |         进入方法前需获取当前对象的锁         |
> |   修饰静态方法   | 类的 Class 对象  |     Xxx.class（类对象）      |          进入方法前需获取当前类的锁          |
> |  修饰同步代码块  | 括号里指定的对象 | `synchronized(obj)` 中的 obj | 推荐使用，粒度更小，只锁住关键代码，效率更高 |

::: code-group

#### ReentrantLock

ReentrantLock（可重入锁）是 `java.util.concurrent.locks` 包下提供的一种显式锁机制，它实现了 `Lock` 接口，提供了更高程度的灵活性和可控性。

> [!NOTE] 核心特性
>
> - **手动加锁与释放**：不同于 `synchronized` 的自动加锁和释放，ReentrantLock 需要手动调用 `lock()` 和 `unlock()`；
> - **支持公平/非公平锁设置**：
>   - 非公平锁（默认）：新来的线程直接尝试抢锁，抢不到才去排队，吞吐量较高；
>   - 公平锁：严格按照等待队列先到先得的顺序分配锁，可避免线程饥饿，但性能略低；
> - **响应中断**：支持响应线程中断，避免因为死锁或无限等待而死锁；
> - **超时获取锁**：可以指定尝试获取锁的等待超时时间，逾期则放弃，防止长时间阻塞；
> - **精确唤醒**：可以结合 Condition 实现多条件变量的等待/通知机制（比 `wait/notify` 更加精准）；

| 常用方法                   | 功能说明                                                        | 适用场景                 |
|----------------------------|-----------------------------------------------------------------|--------------------------|
| lock()                     | 获取锁，如果锁被其他线程占用，则当前线程阻塞等待                | 标准加锁                 |
| unlock()                   | 释放锁，只有持有该锁的线程才能调用，否则抛出异常                | 必须放在 finally 中      |
| tryLock()                  | 尝试获取锁，如果锁处于空闲状态则立即返回 true，否则返回 false   | 避免长时间阻塞的轮询场景 |
| tryLock(timeout, timeUnit) | 在给定的时间内尝试获取锁，超时未获取则返回 false                | 带有超时机制的锁竞争     |
| lockInterruptibly()        | 尝试获取锁，但允许在等待过程中响应 `Thred.interrupt()` 中断信号 | 可被中断的高级加锁       |

::: code-group

```java [Main]
public static void main(String[] args) throws InterruptedException {
  ReentrantLockExample lockExample = new ReentrantLockExample();

  Thread t1 = new Thread(() -> {
    for (int i = 0; i < 10000; i++) {
      lockExample.increment();
    }
  }, "线程1");
  Thread t2 = new Thread(() -> {
    for (int i = 0; i < 10000; i++) {
      lockExample.increment();
    }
  }, "线程2");

  t2.start();

  t1.join();
  t2.join();

  System.out.println("最终Count值：" + lockExample.getCount());
```

```java [非公平锁] {3,8,14}
public class ReentrantLockExample {
  // 创建锁对象，默认是非公平锁，传 true 可以显式设置为公平锁
  private final ReentrantLock lock = new ReentrantLock();
  private int count = 0;

  public void increment() {
    // 显式加锁
    lock.lock();
    try {
      this.count++;
      System.out.println(Thread.currentThread().getName() + " 当前计数：" + this.count);
    } finally {
      // 最终必须释放锁
      lock.unlock();
    }
  }

  public int getCount() {
    return this.count;
  }
}
```

```java [超时锁] {8,14,22}
public class ReentrantLockExample {
  // 创建锁对象，默认是非公平锁，传 true 可以显式设置为公平锁
  private final ReentrantLock lock = new ReentrantLock();
  private int count = 0;

  public void increment() {
    try {
      if (lock.tryLock(2, TimeUnit.SECONDS)) {
        try {
          // 获取到锁后的业务操作
          this.count++;
          System.out.println(Thread.currentThread().getName() + " 当前计数: " + count);
        } finally {
          lock.unlock();
        }
      } else {
        // 在规定时间内没有抢到锁的替代逻辑
        System.out.println("获取锁超时，放弃操作！");
      }
    } catch (InterruptedException e) {
      // 中断当前线程，不再抢锁
      Thread.currentThread().interrupt();
    }
  }

  public int getCount() {
    return this.count;
  }
}
```

### CAS 与原子类

在多线程编程中，CAS（Compare-And-Swap，比较并交换）是实现无锁并发的核心底层机制，而原子类（Atomic Classes）则是 Java 基于 CAS
封装好、供开发者使用的高级并发工具。

> [!NOTE] 什么是 CAS？
>
> CAS 是一种 **乐观锁** 思想的实现，它在更新变量时， **不进行加锁**，而是假设没有其他线程竞争，如果在真正写入时发现变量已经被其他线程修改了，就不断重试（自旋），直到成功为止。

> [!NOTE] 什么是原子类？
>
> `java.util.concurrent.atomic` 包下提供了一系列原子类。这些类内部使用 CAS 指令（通过 Unsafe 类或
> VarHandle）来实现无锁的安全操作，避免了传统锁（如 `synchronized`）带来的线程上下文切换开销。
>
> 常用的原子类分类：
>
> |           类型           | 原子类                                                       |
> | :----------------------: | ------------------------------------------------------------ |
> |         基本类型         | AtomicInteger、AtomicLong、AtomicBoolean                     |
> |         引用类型         | AtomicReference、AtomicStampedReference（带版本号，解决 ABA 问题） |
> |         数组类型         | AtomicIntegerArray、AtomicLongArray                          |
> | 累加器（高并发性能更强） | LongAdder、DoubleAdder                                       |

> [!CAUTION] CAS 缺点
>
> 尽管 CAS 性能很高，但它也有三个经典隐患：
>
> 1. ABA 问题
>    - **现象**：线程 1 读取变量值为 A，准备修改。此时线程 2 将变量从 A 改为 B，随后又改为了 A。当线程 1 执行 CAS，发现值依然是
       A，判定没有被修改过，从而更新成功。
>    - **影响**：对基本数据类型影响不大，但对链表/栈等复杂数据结构会导致结构损坏或逻辑错误。
>    - **解决方案**：使用带版本号/时间戳的原子类，如 AtomicStampedReference，每次修改不仅比较值，还比较版本号。
> 2. 循环开销大（自旋开销）
>    - **影响**：如果高并发下竞争极度激烈，CAS 频繁失败，线程会处于死循环状态，极度消耗 CPU 资源。
>    - **解决方案**：在高并发累加场景下，推荐使用 `LongAdder` 替代 `AtomicLong` （分段累计）。
> 3. 只能保证单一共享变量的原子操作
>    - **影响**：CAS 只能针对一个变量进行原子操作。
>    - **解决方案**：如果需要同时保护多个变量的原子性，可以将多个变量封装进一个对象，使用 `AtomicReference` 来更新整个对象。

| 常用方法                      | 描述                                   | 对应普通操作 |
|-------------------------------|----------------------------------------|--------------|
| get()                         | 获取当前值                             | 读取变量     |
| set(newValue)                 | 设置当前值                             | x = newValue |
| getAndIncrement()             | 获取当前值并自增 1                     | x++          |
| incrementAndGet()             | 自增 1 并返回新值                      | ++x          |
| getAndAdd(int delta)          | 获取当前值并增加 delta                 | x += delta   |
| compareAndSet(expect, update) | 如果当前值等于 expect，则更新为 update | 显式执行 CAS |

::: code-group

```java [基础原子类] {3,9,20}
public class Main {
  // 创建初始值为 0 的原子类整数
  private static final AtomicInteger count = new AtomicInteger(0);

  public static void main(String[] args) throws InterruptedException {
    Runnable task = () -> {
      for (int i = 0; i < 10000; i++) {
        // 使用内部方法确保自增的原子性，相当于 count++
        count.incrementAndGet();
      }
    };
    Thread t1 = new Thread(task);
    Thread t2 = new Thread(task);

    t1.start();
    t2.start();
    t1.join();
    t2.join();

    System.out.println("最终结果：" + count.get());
  }
}
```

```java {2,6,10} [compareAndSet自定义无锁逻辑]
public class Main {
  private static final AtomicReference<String> status = new AtomicReference<>("INIT");

  public static void main(String[] args) throws InterruptedException {
    // 尝试从 "INIT" 改为 "RUNNING"

    boolean fail = status.compareAndSet("INIT", "STOPPED");

  }
}
```

### volatile

volatile 是一个轻量级的同步关键字，它主要用于解决多线程环境下共享变量的 **可见性** 和 **有序性** 问题，但不保证
**原子性**。

> [!NOTE] 核心特性
>
> ① 保证线程可见性
>
> 在没有 volatile 修饰时，每个线程在运行时都会将主内存中的变量拷贝一份副本到自己的工作内存。如果线程 A 修改了变量，线程 B
> 可能无法立即看到修改后的值，导致“数据脏读”。
>
> 当一个变量被声明为 volatile 时：
>
> - 写入时：线程对该变量的修改会 **立即刷新回到主内存**；
> - 读取时：其他线程读取该变量时，会强制 **从主内存中重新加载最新值**，而不是读取本地工作内存的缓存；
>
> ② 禁止指令重排
>
> 为了优化性能，编译器和 CPU 在不改变单线程执行结果的前提下，可能会对代码指令进行重排序。但在多线程环境下，这种重排可能会引发严重
> Bug。
>
> volatile 关键字通过在编译时插入 **内存屏障**，禁止了这种指令重排序，确保代码按照预期顺序执行。

::: code-group

```java [Main]
public static void main(String[] args) throws InterruptedException {
  TaskRunner task = new TaskRunner();
  // 创建并启动子线程
  Thread t = new Thread(task);
  t.start();
  // 主线程休眠1秒
  Thread.sleep(1000);
  // 主线程调用 stop() 停止子线程
  task.stop();
}
```

```java [TaskRunner] {3}
public class TaskRunner implements Runnable {
  // 使用 volatile 保证 flag 的修改能被其他线程立即感知
  private volatile boolean running = true;

  public void stop() {
    // 主线程调用 stop()，会立即刷新到主内存
    this.running = false;
  }

  @Override
  public void run() {
    while (running) {
      try {
        Thread.sleep(300);
        System.out.println("线程正在执行中");
      } catch (InterruptedException e) {
        throw new RuntimeException(e);
      }
    }
    System.out.println("线程已安全停止");
  }
}
```
