# 模块聚合

模块聚合是一种将多个 Maven 项目组织管理在同一个父项目下的机制。通过模块聚合，只需要在顶层父项目上执行一条 Maven 命令，就可以自动遍历并构建所有的子模块，无需手动挨个去创建。

> [!NOTE] 核心优势
>
> - **一键构建**：通过父项目统一执行命令，一次性编译、测试、打包所有子模块；
> - **反应堆依赖排序**：Maven 会自动分析子模块之间的依赖关系，并按照正确的先后顺序进行构建；
> - **清晰的项目结构**：将庞大的应用拆分为多个高内聚、低耦合的模块；



## 构建多模块项目

假设我们要构建一个简单的应用系统，拆分为以下两个子模块：

- `app-core`：核心业务逻辑与数据处理；
- `app-web`：Web 应用层，依赖 `app-core`；



### 项目目录结构

创建一个根目录文件夹 `my-app`，并在其中放置父 `pom.xml` 和各个子模块目录：

```tex
my-app/
├── pom.xml               <-- 顶层父项目的 pom.xml
├── app-core/
│   └── pom.xml           <-- 子模块 app-core 的 pom.xml
└── app-web/
    └── pom.xml           <-- 子模块 app-web 的 pom.xml
```



### 配置父项目

在父项目的 `pom.xml` 中，最关键的是将打包类型 `<packaging>` 设置为 `pom`，并在 `<modules>` 标签内指定子模块的相对路径文件夹名：

```xml {9,12-15}
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>org.example</groupId>
  <artifactId>my-app</artifactId>
  <version>1.0.0</version>
  <!-- 父模块打包类型必须设置为 pom -->
  <packaging>pom</packaging>

  <!-- 声明聚合的子模块文件夹路径 -->
  <modules>
    <module>app-core</module>
    <module>app-web</module>
  </modules>
</project>

```



### 配置子模块

子模块可以通过 `<parent>` 继承父项目的配置（通常聚合与继承结合使用）：

::: code-group

```xml [app-core] {10-14}
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <artifactId>app-core</artifactId>
  <!-- 子模块打包类型为 jar 包 -->
  <packaging>jar</packaging>

  <!-- 继承的父项目配置，配置了父项目之后，子项目可以省略 groupId 和 version -->
  <parent>
    <groupId>org.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>
  </parent>

  <properties>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
</project>
```

```xml [app-web] {10-14}
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <artifactId>app-web</artifactId>
  <!-- 子模块打包类型为 war 包 -->
  <packaging>war</packaging>

  <!-- 继承的父项目配置，配置了父项目之后，子项目可以省略 groupId 和 version -->
  <parent>
    <groupId>org.example</groupId>
    <artifactId>my-app</artifactId>
    <version>1.0.0</version>
  </parent>

  <properties>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <dependencies>
    <!-- 引入兄弟模块 app-core 依赖 -->
    <dependency>
      <groupId>org.example</groupId>
      <artifactId>app-core</artifactId>
      <version>${project.version}</version>
    </dependency>
  </dependencies>

  <!-- 添加 build 节点和 maven-war-plugin 配置 -->
  <build>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-war-plugin</artifactId>
        <version>3.3.2</version>
        <configuration>
          <failOnMissingWebXml>false</failOnMissingWebXml>
        </configuration>
      </plugin>
    </plugins>
  </build>
</project>

```

:::



### 执行聚合构建

打开 Maven 工具，在 `my-app` 中执行打包命令：

```bash
mvn clean package
```

构建日志输出效果（Maven Reactor 拓扑排序）：

```tex
[INFO] Reactor Build Order:
[INFO] 
[INFO] my-app                                                              [pom]
[INFO] app-core                                                            [jar]
[INFO] app-web                                                             [war]
[INFO] 
[INFO] ------------------------------------------------------------------------
[INFO] Building my-app 1.0.0
[INFO] ------------------------------------------------------------------------
...
[INFO] ------------------------------------------------------------------------
[INFO] BUILD SUCCESS
[INFO] ------------------------------------------------------------------------
```

Maven 识别到了 `app-web` 依赖 `app-core`，因此自动调配顺序，先构建 `app-core`，再构建 `app-web`。
