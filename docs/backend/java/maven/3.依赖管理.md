# 依赖管理

在 Java 开发中，依赖（Dependency）就是你的项目需要用到的第三方代码库，而 Maven 的依赖管理，就是一个自动帮你下载、管理和更新这些代码库的“大管家”。



## 核心配置

`pom.xml` 是 Maven 项目的核心配置文件，该文件中有一些关键参数需要了解。

::: code-group

```xml [pom.xml] {34,42}
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <!-- 当前 pom.xml 文件遵循的 Maven 模型版本 -->
  <modelVersion>4.0.0</modelVersion>

  <!-- 当前项目的 G，定义所属的组织或公司，通常使用公司域名倒写 -->
  <groupId>org.example</groupId>
  <!-- 当前项目的 A，定义具体项目或模块的名称 -->
  <artifactId>demo1</artifactId>
  <!-- 当前项目的 V，定义项目的版本号 -->
  <version>1.0-SNAPSHOT</version>
  <!-- 当前项目的 P，定义项目最终要打包为什么格式 -->
  <packaging>jar</packaging>

  <!-- 项目的展示名称 -->
  <name>demo1</name>
  <!-- 项目的官方主页地址，如果代码开源，这里填写 Github 地址 -->
  <url>http://maven.apache.org</url>

  <!-- 定义项目的全局属性 -->
  <properties>
    <!-- 指定源代码的 Java 语言版本 -->
    <maven.compiler.source>21</maven.compiler.source>
    <!-- 指定编译后生成字节码文件的 JVM 版本 -->
    <maven.compiler.target>21</maven.compiler.target>

    <!-- 上面两个标签的合体 -->
    <!-- <maven.compiler.release>21</maven.compiler.release> -->

    <!-- 指定使用 UTF-8 编码来读取和编译源代码 -->
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <!-- 提取 lombok 的依赖 -->
    <lombok.version>1.18.46</lombok.version>
  </properties>

  <dependencies>
    <!-- 引入 lombok 依赖 -->
    <dependency>
      <groupId>org.projectlombok</groupId>
      <artifactId>lombok</artifactId>
      <version>${lombok.version}</version> <!-- 使用 ${} 的方式插入 -->
      <scope>compile</scope>
    </dependency>
  </dependencies>
</project>

```

:::





## 三大核心机制

### 仓库管理

当你声明了一个依赖，Maven 会自动按顺序去以下地方寻找：

- **本地仓库**：在 Maven 安装目录的 `repository` 目录下，下载过一次的库会存在这里，下次直接使用，不用重新联网下载；
- **远程/私服仓库**：下载公司内部或指定服务器上的代码库，通常用于团队内部共享代码；
- **中央仓库**：Maven 官方维护的全球最大的资源中学，几乎所有的主流 Java 开源库都在这里；



### 依赖传递

依赖传递是 Maven 最强大的功能之一。假设项目需要“库 A”，而“库 A”在运行中又依赖了“库 B”。此时只需要在 `pom.xml` 中引入 A，Maven 会自动把 B 也下载下来。

这样省去了开发者手动梳理复杂的依赖树的时间，并且避免了版本不兼容问题。



### 依赖作用域

依赖作用域用于控制依赖库在项目的哪个阶段起作用。常见的作用域有：

|  作用域  | 描述                                                         |
| :------: | ------------------------------------------------------------ |
| compile  | 默认。编译、测试、运行阶段都需要该库                         |
|   test   | 只在测试阶段有效，打包发布时不会包含它                       |
| provided | 编译和测试时需要，但真正在服务器上运行时，有服务器（如Tomcat）来提供，不需要打包进去 |

```xml {5,12,19}
<dependency>
  <groupId>org.projectlombok</groupId>
  <artifactId>lombok</artifactId>
  <version>1.18.46</version>
  <scope>compile</scope>
</dependency>

<dependency>
  <groupId>org.junit.jupiter</groupId>
  <artifactId>junit-jupiter-api</artifactId>
  <version>6.1.3</version>
  <scope>test</scope>
</dependency>

<dependency>
  <groupId>javax.servlet</groupId>
  <artifactId>javax.servlet-api</artifactId>
  <version>4.0.1</version>
  <scope>provided</scope>
</dependency>
```
