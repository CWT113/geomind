# 密封类

Java17 中新引入了 **密封类**（Sealed Classes）的概念，它允许你 **明确指定哪些类可以继承** 或实现特定的类或接口。就好像给类加了一把锁，只有得到授权的子类才能继承。



## 核心语法

> [!NOTE] 语法规则
>
> - 密封类使用关键字 `sealed` 声明，并且必须使用 `permits` 关键字明确列出允许继承的子类；
> - 允许继承的子类，必须使用以下关键字声明：
>   - `final` 类：禁止进一步继承；
>   - `sealed` 类：继续限制继承；
>   - `non-sealed` 类：开放继承；

```java [密封类] {1}
public sealed class Shape permits Circle, Rectangle, Triangle {
}

// final类：禁止进一步继承
final class Circle extends Shape {
}

// sealed类：继续限制继承
sealed class Rectangle extends Shape {
}

// non-sealed类：开放继承
non-sealed class Triangle extends Shape {
}
```



## 子类的三种类型

### final 子类

`final` 子类是最常见的，表示这个类不能再被继承了，是继承链的终点。

```java
final class Circle extends Shape {
  private final double radius;

  public Circle(double radius) {
    this.radius = radius;
  }
}

class Temp extends Circle {} // 错误：final类不允许继承 // [!code --]
```



### sealed 子类

`sealed` 子类表示这个类也是密封类，可以继续限制它的子类。

```java {2,13}
// 密封类必须通过 permits 指定它的可继承类
sealed class Rectangle extends Shape permits TransparentRectangle {
  private final double width;
  private final double height;

  public Rectangle(double width, double height) {
    this.width = width;
    this.height = height;
  }
}

// Rectangle的子类
final class TransparentRectangle extends Rectangle {
  public TransparentRectangle(double width, double height) {
    super(width, height);
  }
}
```



### non-sealed 子类

`non-sealed` 子类表示这个类不再密封，任何类都可以继承它。

```java {2}
// 解除密封，任何类都可以继承该类
non-sealed class Triangle extends Shape {
  private final double side;

  public Triangle(double side) {
    this.side = side;
  }
}

class CustomTriangle extends Triangle {
  public CustomTriangle(double side) {
    super(side);
  }
}
```



## 绝配特性

密封类并不是孤立存在的，它与 Java 引入的其他特性可以完美配合。



### 配合 record

`record` 记录类型隐式带有 `final` 属性，因此非常适合作为密封类的子类。

```java
public sealed interface ServiceResponse permits SuccessResponse, ErrorResponse {
}

public record SuccessResponse(Integer code, String message) implements ServiceResponse {
}

public record ErrorResponse(Integer code, String message) implements ServiceResponse {
}
```



### 配合模式匹配

在配合 `switch` 进行类型判断时，由于编译器明确知道密封类只有哪几种子类，因此不再强制要求编写 default 分支。

```java
public static String getShapeInfo(Shape shape) {
  // 不需要 default 分支，因为编译器知道 Shape 只有 Circle, Rectangle, Square 三种子类
  return switch (shape) {
    case Circle c -> "这是一个圆形，半径为: " + c;
    case Rectangle r -> "这是一个长方形";
    case Square s -> "这是一个正方形";
  };
}
```
