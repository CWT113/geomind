# 异常处理和拦截器

## 异常处理

SpringMVC 中的异常处理器是一种 **统一拦截和处理 Web 层未捕获异常的机制**。它将 Controller 及后续组件抛出的异常从业务逻辑中解耦出来，避免直接向客户端暴漏 500 等堆栈错误，并统一转换为友好的错误页面或结构化 JSON 数据。

SpringMVC 的异常解析底层基于 `HandlerExceptionResolver` 接口：

```java
public interface HandlerExceptionResolver {
  @Nullable
  ModelAndView resolveException(
    HttpServletRequest request,
    HttpServletResponse response, 
    @Nullable Object handler,
    Exception ex
  );
}
```

当请求执行链路抛出未处理异常时，`DispatcherServlet` 会遍历所有注册的 `HandlerExceptionResolver` 实现，只要有一个返回非 `null` 的 `ModelAndView`，该异常即被认为已处理完成。



### 默认异常处理器

`DefaultHandlerExceptionResolver` 是 `HandlerExceptionResolver` 的默认实现，已经在 SpringMVC 中内置。

```java
public class DefaultHandlerExceptionResolver extends AbstractHandlerExceptionResolver {
  // ...
  
  // 请求不支持时拦截的异常
  @Nullable
  protected ModelAndView handleHttpRequestMethodNotSupported(HttpRequestMethodNotSupportedException ex, HttpServletRequest request, HttpServletResponse response, @Nullable Object handler) throws IOException {
    return null;
  }

  // MediaType不支持时抛出的异常
  @Nullable
  protected ModelAndView handleHttpMediaTypeNotSupported(HttpMediaTypeNotSupportedException ex, HttpServletRequest request, HttpServletResponse response, @Nullable Object handler) throws IOException {
    return null;
  }

  // ...
}
```



### 自定义异常处理

自定义异常处理器需要实现 `SimpleMappingExceptionResolver` 类。

#### 配置文件方式

```xml {42-52}
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:context="http://www.springframework.org/schema/context"
       xmlns:mvc="http://www.springframework.org/schema/mvc"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
                           http://www.springframework.org/schema/beans/spring-beans.xsd
                           http://www.springframework.org/schema/context
                           https://www.springframework.org/schema/context/spring-context.xsd http://www.springframework.org/schema/mvc https://www.springframework.org/schema/mvc/spring-mvc.xsd">
  <!-- 配置组件扫描 -->
  <context:component-scan base-package="com.example.controller"/>

  <!-- 启用注解式 MVC -->
  <mvc:annotation-driven>
    <!-- 允许使用 fastjson2 把 HTTP 请求里的 JSON 转换为 Java 对象 -->
    <mvc:message-converters>
      <bean class="com.alibaba.fastjson2.support.spring6.http.converter.FastJsonHttpMessageConverter"/>
    </mvc:message-converters>
  </mvc:annotation-driven>

  <!-- 配置 Thymeleaf 视图解析器 -->
  <bean id="thymeleafViewResolver" class="org.thymeleaf.spring6.view.ThymeleafViewResolver">
    <property name="characterEncoding" value="UTF-8"/>
    <property name="order" value="1"/>
    <property name="templateEngine">
      <bean class="org.thymeleaf.spring6.SpringTemplateEngine">
        <property name="templateResolver">
          <bean class="org.thymeleaf.spring6.templateresolver.SpringResourceTemplateResolver">
            <!-- 设置模板文件的前缀 -->
            <property name="prefix" value="/WEB-INF/templates/"/>
            <!-- 设置模板文件的后缀 -->
            <property name="suffix" value=".html"/>
            <property name="templateMode" value="HTML"/>
            <property name="characterEncoding" value="UTF-8"/>
          </bean>
        </property>
      </bean>
    </property>
  </bean>

  <!-- 配置自定义异常 -->
  <bean class="org.springframework.web.servlet.handler.SimpleMappingExceptionResolver">
    <!-- 配置 order 属性靠前一些，因为默认 SpringMVC 使用了 DefaultExceptionResolver 会拦截掉 -->
    <property name="order" value="0"/>
    <property name="exceptionMappings">
      <props>
        <!-- 可以显式指定 405 异常类型，或者保留 java.lang.Exception -->
        <prop key="org.springframework.web.HttpRequestMethodNotSupportedException">tip</prop>
        <prop key="java.lang.Exception">tip</prop> <!-- 返回 templates\tip.html 文件 -->
      </props>
    </property>
  </bean>
</beans>
```

当一个接口请求方式不正确时，就会出发自定义的异常处理器，然后返回自定义的 `tip.html` 页面。



#### 注解方式

```java {4}
@ControllerAdvice
@Order(Ordered.HIGHEST_PRECEDENCE) // 将当前的异常处理器优先级设置为最高
public class GlobalExceptionHandler {
  @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
  public String handleMethodNotSupported(HttpRequestMethodNotSupportedException e, Model model) {
    model.addAttribute("message", "请求方式不支持：" + e.getMessage());
    return "tip"; // 返回 templates\tip.html
  }

  // 可以自定义很多种类的异常
  @ExceptionHandler(Exception.class)
  public String handleException(Exception e, Model model) {
    return "exception";
  }
}
```





## 拦截器

SpringMVC 中的拦截器（HandlerInterceptor）是一种专门 **针对请求处理流程进行横切拦截的组件**，底层基于 Java 的反射与动态代理 **（AOP 思想）实现**。

它主要用于在 **请求到达具体的 Controller 之前、执行之后**、以及视图渲染完成之后插入通用逻辑（如登录认证、权限检查、日志审计、接口耗时统计等）。

> [!NOTE] 过滤器和拦截器区别
>
> >比如过滤器是学校，则拦截器便是教室。进入学校时要刷脸，此时过滤器生效，进入教室时要签到，此时拦截器生效。
>
> |  比较维度  | 过滤器（Filter）                                    | 拦截器（Interceptor）         |
> | :--------: | --------------------------------------------------- | ----------------------------- |
> | 规范与归属 | 基于 Servlet 规范，归属于 Servlet 容器（如 Tomcat） | 基于 Spring 框架，归属于 MVC 体系 |
> | 拦截范围 | 拦截所有请求（包括静态资源 HTML、CSS、图片及所有 Servlet） | 仅拦截到达 DispatcherServlet 的 Contoller 请求 |
> | 执行时机 | 请求进入 DispatcherServlet 之前和之后 | 请求进入 DispatcherServlet 后，到达 Controller 之前和之后 |



### 定义拦截器

实现 `HandlerInterceptor` 接口通常需要重写以下三个生命周期方法：

|    核心方法     | 执行时机                                         | 描述                                                         |
| :-------------: | :----------------------------------------------- | :----------------------------------------------------------- |
|    preHandle    | 在 Controller 方法调用之前执行                   | 返回 true 表示放行，返回 false 则中断流程，不再执行后续拦截器和 Controller |
|   postHandle    | 在 Controller 方法执行完成之后、视图渲染之前执行 | 可以对请求域中的数据或视图名进行修改                         |
| afterCompletion | 在整个请求处理完成后执行                         | 主要用于资源清理、记录执行异常或统计请求总耗时               |
